# NYC Restaurant Market Platform

An exploratory NYC restaurant dashboard built with Python, SQLite and browser JavaScript. The map shows cuisine supply across official NTA areas and published retail rent benchmarks for selected Manhattan corridors.

## Interactive demo

The homepage is `index.html`. It contains its data and map geometry and can be opened offline. After GitHub Pages is enabled for `main` and the repository root, the Pages settings will show the published URL. Deployment has not yet been completed.

## Main findings and scope

The neighborhood map spatially matches 30,655 of 31,469 establishment records (97.4%). Cuisine heat can show counts or shares of local mapped records with known cuisine. Rent markers represent 16 approximate Manhattan corridor anchors, with 14 current medians and two unavailable values. Both measures retain source definitions and observation dates.

The dashboard supports users who know a cuisine, know a location, or are still exploring. It includes supply, rent, delivery and market-context modules. Public observations support research comparisons; business usefulness and investment outcomes require further validation.

See `GITHUB_DEPLOYMENT.md`. `build_dashboard.py` writes both the original named HTML and `index.html`, so a rebuild also updates the Pages homepage. `.nojekyll` lets GitHub serve the static files directly.

## Reproduction

Use Python 3.10+ and the recorded dependencies in `requirements.txt`. Run from this directory:

```bash
python build_analysis.py
python build_geography.py
python make_charts.py
python make_map_charts.py
python build_dashboard.py
python build_final_handoff.py
```

All six commands work from the bundled frozen data without downloading reports. The document builder also creates the editable BA registers and blank UAT log; preserve completed user observations elsewhere before rerunning it. The HTML requires no server or dependency installation for viewing.

The previous `make_materials.py` generates the original preliminary brief and overwrites README and source metadata. It is retained for provenance only; do not run it as part of this final release. The earlier brief and meeting notes are in `archive/`.

For browser regression checks, install Node, Playwright and a Chromium browser, then run `node verify_dashboard.cjs`. Set `NYC_CHROMIUM_PATH` if using a separately installed browser. The script tests filters, exports, empty states, rent input, period comparisons, mobile layout and JavaScript errors. Screenshots generated by the test are local QA outputs and are excluded from the delivery archive.

Refresh sources deliberately with `fetch_sources.py` in a separate working copy. Publisher revisions can alter history and schema. Review the frozen-period guards, source captures, narratives and dashboard labels before publishing a new release. Do not mix refreshed raw inputs with old report claims.

## Neighborhood maps

MAP_GUIDE.md defines the spatial matching and heat measures. The map uses 262 official NTAs and matches 30,655 restaurant records. Counts and local cuisine shares can be compared by borough. Rent uses 16 approximate Manhattan corridor anchors with no imputed neighborhood or other-borough rent. Map data are embedded in the HTML, so viewing needs no tile service or API key.

## Model boundaries

Supply uses unique CAMIS records and publisher cuisine categories. All facts retain their native geography and period. No verified relationship joins Manhattan retail corridors to ZIP codes or allocates citywide delivery totals to individual restaurants. Cuisine shares are supply shares, not revenue shares. The platform does not estimate restaurant profit or success probability.

The prototype is an offline review artifact. Native BI workbooks, live hosting, user accounts, scheduled refresh, demand enrichment and opportunity ranking are deferred. Sponsor approval, user interviews and user acceptance results are not claimed. Proposed roles, thresholds and current-workflow assumptions require confirmation.

The prior browser pass is historical and does not validate the map release. New Node calculation and JSDOM behavior tests pass; real browser layout and SVG pointer panning remain unverified. See qa/map_checks.json. Install jsdom 26.1.0 to run `node verify_maps.cjs`. Run `python verify_final_release.py` for data and structure controls.
